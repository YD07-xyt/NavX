## 1. 项目概述

### 1.1 定位

ROG-Map 是面向**无人机 / 机器人局部规划**的实时占据栅格地图系统。不同于建图与定位（SLAM）中的全局地图，ROG-Map 维护一个以机器人为中心的**滑动窗口局部地图**，兼顾：

- **实时性**：毫秒级更新（射线投射 + 概率更新 + 膨胀层）
- **低内存**：固定大小的环形缓冲，不需要动态分配
- **完整性**：同时提供概率占据层、膨胀层、ESDF、前沿、地形分析

### 1.2 输入 / 输出

**输入：**

| 数据 | 格式 | 说明 |
|------|------|------|
| 点云 | `pcl::PointCloud<pcl::PointXYZI>` | 传感器（LiDAR）实时点云，含 intensity |
| 里程计 | `Pose = std::pair<Vec3f, Quaternion>` | 机器人位姿，用于确定窗口中心和射线起点 |
| 配置 | YAML 文件 | 地图分辨率、更新范围、概率参数等 |

**输出：**

| 输出 | 说明 |
|------|------|
| 概率占据栅格 | 每个 cell 存储 log-odds 占据概率值 |
| 膨胀层 (InfMap) | 基于 CounterMap 的占据/未知区域膨胀，用于碰撞检测 |
| ESDF | 基于增量 3D EDT 算法的欧几里得符号距离场 |
| 前沿点 (Frontier) | 已知自由 ↔ 未知 边界，用于探索 |
| 地形分析图 | 2.5D 通行性分析，用于足式/轮式地面机器人 |

## 3. 核心算法详解

### 3.1 环形滑动窗口 (SlidingMap)

**核心思想：** 固定大小的环形缓冲（toroidal buffer），以机器人位置为中心滑动地图窗口。

**数据组织：**

- 地图大小固定为 `(2*half_map_size_i+1)` 的 3D 数组，总 voxel 数恒定
- `local_map_origin_i_` 表示窗口中心对应的全局网格坐标
- 通过取模运算实现环形索引映射：
  - 全局索引 → 本地索引：`id_l(i) = id_g(i) % map_size_i(i)` 再归一化到 `[-half, half]`
  - 哈希：`hash = id_l(0)*s1*s2 + id_l(1)*s2 + id_l(2)`

**滑动过程**（`mapSliding`）：

1. 计算新中心与旧中心的移位 `shift_num`
2. 对每个维度：如果 `shift_num[i] != 0`，计算需要清除的本地索引条带
3. 清除条带（`clearMemoryOutOfMap` → `resetCell`）
4. 更新 `local_map_origin_i_` 和包围盒

**坐标原点策略：** 通过编译宏 `ORIGIN_AT_CORNER` / `ORIGIN_AT_CENTER` 选择。

- `ORIGIN_AT_CORNER`：原点在 cell 角点，`posToGlobalIndex` 使用 `floor`
- `ORIGIN_AT_CENTER`：原点在 cell 中心，`posToGlobalIndex` 使用四舍五入

**优点：** 无动态内存分配，索引计算 O(1)，内存恒定可控。  
**缺点：** 滑动时需清除整条数据，滑动成本随地图大小线性增长；数学上坐标越界恢复复杂。

### 3.2 概率占据更新 (ProbMap)

**概率表示：** 每个 cell 存储 log-odds 形式的占据概率。

$$L(x) = \log\frac{p(x)}{1-p(x)}$$

**更新公式：**

- Hit：`L += l_hit * hit_num`，封顶 `l_max`（典型值 `l_hit ≈ +0.85`）
- Miss：`L += l_miss * hit_num`，封底 `l_min`（典型值 `l_miss ≈ -0.20`）

**判定阈值：**

- `L ≥ l_occ` → OCCUPIED（典型 `l_occ ≈ +0.80`）
- `L < l_free` → KNOWN_FREE（典型 `l_free ≈ -0.85`）
- 其余 → UNKNOWN

**批处理优化：** `insertUpdateCandidate` 先将更新操作记录到 `operation_cnt` / `hit_cnt`，累积到 `batch_update_size` 帧后一次性批量处理，减少锁竞争和频繁类型翻转。

### 3.3 计数膨胀层 (CounterMap / InfMap)

**核心设计：** Sub-grid voting（子网格投票）。

- 每个 CounterMap cell 包含 `sub_grid_num` 个"虚拟子格"
- `occupied_cnt`：统计被占用的子格数（>0 即视为占据）
- `unknown_cnt`：统计未观测的子格数（≥ `unk_thresh` 视为未知）

**双率分辨率：** CounterMap 的分辨率是概率图的整数倍（`inflation_ratio`），通常更低分辨率以减少内存和计算量。

**膨胀机制：**

- `InfMap::updateInflation`：当概率层发生 UNKNOWN→OCCUPIED 翻转时，将该 cell 的 **球形邻域** 内所有 CounterMap cell 的 `occ_inflate_cnt` += 1；翻转回时 -= 1
- `InfMap::updateUnkInflation`：同理处理 UNKNOWN 膨胀
- 查询时：`occ_inflate_cnt > 0` → 膨胀后占据；`unk_inflate_cnt > 0` → 膨胀后未知

**"Jumping Edge"回调**：类型翻转时触发 `triggerJumpingEdge`，通知 InfMap/ESDFMap/FreeCntMap 联动更新。

### 3.4 ESDF (Euclidean Signed Distance Field)

**算法：** 基于 **增量式 3D EDT**（Euclidean Distance Transform），沿三个维度分别进行扫描传播。

**关键函数 `fillESDF`：**

```cpp
template<typename F_get_val, typename F_set_val>
void fillESDF(F_get_val f_get_val, F_set_val f_set_val,
              const int &start, const int &end, const int &dim, const int &id_l);
```

- 对指定的维度 `dim`，从 `start` 到 `end` 扫描
- 使用已知距离的前向后向传播（类似于 2D 的 Felzenszwalb & Huttenlocher 方法推广到 3D）
- 正距离：到最近 occupied cell 的距离
- 负距离：到最近 known free cell 的距离

**三线性插值：** `evaluateEDT` / `evaluateFirstGrad` / `evaluateSecondGrad` 提供 8 邻域三线性插值，支持亚格子精度的距离和梯度求值，用于规划器中的障碍物梯度排斥。

### 3.5 前沿探测 (FreeCntMap)

**计数规则：** 每个 cell 记录其 26 邻域内已知自由 cell 的数量。

- 当概率层发生 UNKNOWN → KNOWN_FREE 翻转时：对该 cell 的 26 邻域内所有 cell 的 `neighbor_free_cnt` += 1
- 当 KNOWN_FREE → OCCUPIED/UNKNOWN 翻转时：-= 1
- 判定：`neighbor_free_cnt > 0` 且该 cell 本身为 UNKNOWN → 前沿点

## 4. 动态障碍物拖影处理分析

### 4.1 问题背景

在原始 ProbMap 中，概率更新只有两条单向路径：
- **Hit**（占据）：`L += l_hit`，只增不减
- **Miss**（自由）：`L += l_miss`，只减不增

动态障碍物（行人、车辆）经过时将 cell 打到 `l_max` 占据后离开，若身后没有新的射线穿过：
1. 占据值卡死在 `l_max`，形成"**鬼影/残影**"（ghost trail）
2. 即使有 free-ray 穿过，因 `|l_hit| >> |l_miss|`（约 4:1），需要大量 miss 才压回自由，消散极慢
3. 系统**无法区分静态障碍（墙）和动态障碍**，规划器永远认为那里有障碍

### 4.2 设计方案：占据时间衰减 (occupancy time decay)

**核心思路：** 引入**时间维度**，通过"不活跃的占据格随时间自动衰减到自由"来消除拖影。

**设计原则：**

- **衰减触发条件**：仅当 cell 长时间未被 hit（观测到有物体在那里），才启动衰减
- **衰减强度**：每次施加 `occ_decay_rate * l_miss` 的更新
- **静态障碍保护**：hit/miss 比例调制衰减率 — hit_ratio 高的 cell 衰减极慢，无需硬阈值
- **衰减范围**：限制在局部更新框内，避免全图同时衰减的跳变

### 4.3 详细实现

**新增数据结构：**

```cpp
std::vector<float> last_hit_time_;   // 每个 cell 上次被 hit 的墙钟时间(s)
std::vector<float> last_obs_time_;   // 每个 cell 上次被观测(hit或miss)的时间
std::vector<int> total_hit_cnt_;     // 累计 hit 计数
double cur_wall_time_;               // 当前更新时的墙钟时间
```

**`decayOccupancy()` 流程：**

```
for each cell in local_update_box (或全图):
  if last_hit_time_ == 0:  continue          // 从未被 hit，保持无知
  if cell is known_free:   continue          // 已是自由，无需衰减
  if now - last_hit_time_ <= occ_decay_time: continue  // 未超时
  // ---- hit/miss 比例调制 ----
  total_obs = total_hit_cnt + total_miss_cnt
  if total_obs >= occ_decay_min_obs:
    hit_ratio = total_hit_cnt / total_obs
    decay_modulator = 1.0 - hit_ratio
  else:
    decay_modulator = 1.0
  L += l_miss * occ_decay_rate * decay_modulator
  若类型翻转 → 通知 InfMap/ESDFMap/FreeCntMap
```

**`hitPointUpdate` / `missPointUpdate` 修改：**

- Hit 时：更新 `last_hit_time_`、`last_obs_time_`、`total_hit_cnt_`
- Miss 时：**仅**更新 `last_obs_time_`，不写 `last_hit_time_`（这个区分是关键修正）

### 4.4 效果分析

**正常工作场景：**

| 场景 | 行为 | 效果 |
|------|------|------|
| 墙（静态） | 每次 LiDAR 扫过都 hit → `last_hit_time_` 持续刷新 → 不衰减 | 正确保留 |
| 行人穿过（动态） | 经过时 hit 至占据 → 离开后 no hit → 超时后衰减 → 清除 | 拖影消除 |
| 墙离开 LiDAR 范围 | 不再被 hit → 超时 → hit_ratio 高 → 衰减极慢 | 长期保留 |
| 虚检噪声 | 单次 hit，没后续 → 超时 → 衰减清除 | 噪声自清洁 |

**当前配置（`occ_decay_time=1.0`, `occ_decay_rate=4.0`, `occ_decay_min_obs=5`）：**

- 衰减延迟 ≈ 1 秒（从障碍离开到开始衰减）
- 衰减步数 ≈ 从 `l_occ(≈1.10)` 到 `< l_free(≈-0.85)` 需要约 3 步 → 消散约 3×batch_update 帧 ≈ 0.1~0.3s
- 总拖影消除时间 ≈ 1.0~1.5s

### 4.5 优缺点

**优点：**

1. **实现简洁**：仅需在 ProbMap 层插入一个衰减函数，不需要改动膨胀层/ESDF 的接口
2. **参数可调**：四个参数（`occ_decay_time`, `occ_decay_rate`, `occ_decay_min_obs`, `batch_update_size`）覆盖了从关闭到激进的完整调参空间
3. **向后兼容**：`occ_decay_time=0` 时完全不执行，零开销
4. **静态保护机制**：`total_hit_cnt_` 阈值有效避免长期静态障碍被误清
5. **衰减范围限制**：设置在局部更新框内，避免全图批量消散的跳变效应
6. **时钟源可覆盖**：ROS 层使用 ROS 时钟，仿真/回放时时间线同步

**缺点：**

1. **衰减是单向 "miss 冲刷"，而非真正的动态检测**：系统无法区分"障碍离开了"和"障碍被遮挡了"，如果墙被遮挡超过 `occ_decay_time` 则会被误清
2. **静态障碍判定依赖纯 hit 计数**：如果机器人静止，墙始终被 hit 则无问题；但如果快速转弯后远离再返回，原来累计 hit 数 < 20 的格子可能被误清
3. **O(n) 全框扫描**：虽然限制在局部更新框，但本质是全量遍历，对 60×60×6@0.1m 约 216k cells，CPU 压力可控但非最优
4. **衰减步长固定（每次等同 miss），而非自适应**：**无法根据障碍运动速度自适应调整**

### 4.6 已实现改进与待改进方向

**✅ 改进 1（已实现）：hit/miss 比例替代硬阈值**
- 文件：`prob_map.h/cpp`, `config.hpp`, `rog_map.yaml`
- 新增 `std::vector<int> total_miss_cnt_`
- 替换 `occ_decay_hit_thresh` → `occ_decay_min_obs`
- 衰减率由 `l_miss * occ_decay_rate * (1 - hit_ratio)` 调制
- 消除原方案"墙观测不足被误清"和"站住的人走后免疫"两个核心问题

**✅ 改进 2（已实现）：衰减计时器分拆 + 衰减范围限制 + 衰减强度提升**
- 详见 `TERRAIN_MAP_CHANGES.md`

**待改进方向：**

- **空间一致性**：被占据格包围的 cell 延缓衰减，孤立占据格快速衰减
- **双时间尺度 hit 率**：长期/短期 hit_ratio 比值偏离 1 说明状态变化
- **独立 decay 定时器**：将衰减从 `updateProbMap` 剥离，挂到独立 50Hz 定时器，解决频率受 LiDAR 帧率限制的问题

## 5. 高程分析（地形分析）分析

### 5.1 设计思路

TerrainAnalyzer 是一个**2.5D 通行性分析**模块，将 3D 占据点云投影到 2D 栅格上，分析每个格子的垂直结构，判断机器人能否在该位置通行。

**输入：** `occ_map`（3D 占据点云）+ `robot_pose`（用于确定窗口中心）  
**输出：** 通行/不可通行的点云（z=0 通行的网格中心，z=1 不可通行的点）

### 5.2 算法流程

```
SetupGrid(robot_pos)
  └─ 确定分析窗口范围 [pose-size/2, pose+size/2]
  └─ 原点 snap 到 resolution 网格

For each occupied point:
  └─ worldToGrid() → 分配到栅格
  └─ 记录每个格子的所有 z 值

For each grid cell:
  ├─ 提取地面高度 = 最低点 z（min_z）
  ├─ 提取最高点 z（max_z）
  ├─ 中值滤波平滑地面高度
  ├─ 计算邻域高度梯度（8-邻域最大高度差）
  ├─ 障碍判定：
  │   ├─ 梯度 > steep_threshold → 陡峭边缘 → 障碍
  │   └─ 深度间隙分析：
  │       └─ 排序所有 z 值 → 找最大 gap
  │       └─ gap < robot_height → 机器人钻不过去 → 障碍
  └─ 若为障碍 → 输出该格子内高于地面一定阈值的点
```

### 5.3 优缺点

**优点：**

1. **实现简洁**：核心逻辑只有约 150 行，可读性好
2. **网格对齐设计好**：`setupGrid` 将窗口原点对齐到栅格上，避免亚网格抖动——这是经过实战验证的修复
3. **双重判障机制**：同时考虑**高度梯度**（地形起伏）和**深度间隙**（结构悬空），覆盖地面和低空障碍
4. **中值滤波**：有效抑制地面高度估计中的离群噪声
5. **参数 YAML 化**：所有参数（kernel_size, robot_height, steep_threshold 等）在 YAML 中可配置
6. **高频发布**：默认 30Hz，配合网格对齐消除抖动

**缺点：**

1. **2.5D 本质限制**：只能处理"每列一地面"的假设，不支持悬空走廊、多层地形（如立交桥）
2. **地面高度用最小值**：如果地表有植被（灌木、草），min_z 是地面，但可能有低于地面的凹陷或坑洞未被过滤
3. **垂直间隙分析依赖单列排序**：不考虑倾斜结构（如斜坡），斜坡上的 gap 可能被误判为障碍
4. **仅考虑几何信息**：不考虑坡度、粗糙度、材质等通行性指标

### 5.4 设计缺陷与改进建议

**缺陷 1：地面高度提取过于简单——用每个格子的绝对最低点**

改进建议：
- 使用**百分位数**（如 10th percentile）代替绝对最小值，抵抗局部的 outlier 噪声
- 或使用 **RANSAC 地平面拟合** 在每个栅格内拟合一个平面，更鲁棒

**缺陷 2：8-邻域梯度计算只能检测"边缘"，不能检测"坡度"**

改进建议：
- 改用**平面拟合 + 法向量**：为每个格子拟合一个局部平面，计算坡度（法向量与重力方向的夹角）
- 坡度大于阈值的格子标记为不可通行

**缺陷 3：深度间隙分析将多高度层简单地排序找最大 gap**

- 如果有多个障碍层（如横杆+地面），最大 gap 可能在一层障碍上方，但中间还有一层障碍
- 改进：改用**区间合并**——将所有障碍层合并为占据区间，找第一个低于 robot_height 的连续自由区间

**缺陷 4：无时序滤波**

- 单帧分析，容易被 LiDAR 噪点或运动畸变影响
- 改进：对每个格子的 ground 高度做**指数平滑**（`ground_t = α * ground_obs + (1-α) * ground_{t-1}`）

**缺陷 5：输出是点云而非栅格地图**

- 当前输出为点云（`vec_E<Vec3f>`），下游需要自行栅格化
- 改进：直接输出为 2D costmap（Eigen::ArrayXXf 或 nav_msgs/OccupancyGrid）

**总结评价：** TerrainAnalyzer 适合**简单地面环境**（室内、平整地形）的足式/轮式机器人通行性分析。对于复杂地形（陡坡、多层、密集植被），算法过于简化。

## 6. 总体优缺点总结

### 6.1 优点

1. **模块化设计优秀**：SlidingMap → CounterMap → InfMap/ESDFMap/FreeCntMap 的分层设计清晰，职责分明
2. **实时性极好**：环形缓冲 + 批处理 + 增量更新，单帧处理时间通常在 < 1ms
3. **内存可预测**：固定大小的连续内存，无运行时动态分配
4. **底层算法稳健**：Sub-grid voting 机制相比于纯概率更新，在 CounterMap/InfMap 层面数值更稳定
5. **可配置性强**：几乎所有参数都 YAML 化，可根据传感器和场景灵活调整
6. **完整的功能套件**：概率图、膨胀层、ESDF、前沿、地形分析在一个框架内
7. **优秀的中文文档**：`TERRAIN_MAP_CHANGES.md` 详尽记录了迭代过程

### 6.2 缺点

1. **动态障碍处理偏工程而非算法**：时间衰减无法真正区分动态/静态，只是一个"先占据后忘记"的启发式
2. **概率更新缺乏"撤消"能力**：一旦 hit 到 l_max，只能靠缓慢的 miss 降回，无法快速纠正误检测
3. **多分辨率之间的坐标对齐复杂**：`inflation_ratio` 在 `ORIGIN_AT_CENTER` 下需要为奇数，数学推导复杂
4. **ESDF 在窗口滑动时需全量重算**：虽然增量式在连续帧间高效，但地图滑动后的第一次更新需要全量传播
5. **无持久化/序列化**：无法保存/加载地图状态（虽有 PCD 文件读入，但那是初始加载而非运行时持久化）
6. **缺乏多传感器融合**：只处理单一点云输入，没有 IMU/里程计紧耦合
