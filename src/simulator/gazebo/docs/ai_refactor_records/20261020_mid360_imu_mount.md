# Mid-360 IMU 挂载与传感器参数对齐实物 改造记录

## User Intent

1. 把 IMU 挂到雷达（`livox_frame`）下面，随雷达位置/姿态参数一起移动。
2. 仿照现实的 Livox Mid-360 调整 IMU / LiDAR 参数，使仿真数据与实物一致。
3. 用途：给 Super-LIO 等 LIO 里程计做仿真验证。

### Active logic path

`xacro:mid360` 宏 → `<gazebo reference="livox_frame">` ray 传感器 → `libros2_livox.so`
→ `/livox/lidar`（CustomMsg）。IMU 走独立 `<gazebo reference="imu_link">` imu 传感器
→ `libgazebo_ros_imu_sensor.so` → `/livox/imu`。二者由 URDF 固定关节刚性连接，
`base_link → livox_frame → imu_link`。

### Data flow

Gazebo 物理 1 kHz → IMU 传感器 200 Hz 采样（含重力加速度，m/s²）→ `/livox/imu`；
ray 传感器 10 Hz、每帧 20000 点（200k 点/s）→ `/livox/lidar`。
Super-LIO 用 `lio.extrinsic.lidar_imu` 把 LiDAR 点云变换到 IMU 系，**不查 TF**。

### Risk notes

1. Super-LIO 不查 TF，也没对 IMU 做单位换算，`imu_type` 读而未用；
   其初始化会用 `gravity_norm / mean_acce.norm()` 自标定，所以 **m/s² 是安全的**。
2. 插件的 `offset_time` 是「本帧循环构建点云的实际耗时」，不是 100 ms 扫描周期分布；
   而 Gazebo 一帧点云本身是同一物理时刻的刚体快照，给大偏移反而会造成错误去畸变。
   保持现状最自洽，见 "未解决问题"。
3. 插件不读取 ray `<noise>`，`noise_stddev` 对点云实际不起作用（已在 xacro 里注明）。
4. 旧 `imu_joint` 用 `rpy="3.14 0 0"` 且 parent 是 `base_link`，与雷达挂载参数解耦，
   所以改雷达 `xyz`/`rpy` 时 IMU 不跟着动 —— 这是用户本次要修的问题根因。

### Recommended modification boundary

只改两个 xacro：IMU 关节改挂 `livox_frame`、IMU 传感器参数对齐实物；
LiDAR 量程与噪声属性对齐实物数值。不动插件与 LIO 侧配置。

### Key changes

1. `imu_joint`：parent `base_link → livox_frame`，origin `-0.038 0 0.433 (rpy 3.14 0 0)`
   → `0.011 0.02329 -0.04412 (rpy 0 0 0)`。
   偏移量由本仓库 `lio.extrinsic.lidar_imu = [-0.011,-0.02329,0.04412, I]` 取反得到，
   保证仿真几何与 LIO 内部外参假设一致。
2. `imu_link`：删掉 5 cm 立方体的 visual/collision（原来那个绿色方块就是 IMU 模型，
   用户曾误认为"不明方块"），只保留 inertial。
3. `mid360_imu`：`update_rate 100 → 200`（实物 IMU 输出频率），
   新增 `<imu>` 高斯噪声模型：角速度 σ=0.002 rad/s，加速度 σ=0.02 m/s²
   （按实物量级估计，非手册标称值，可改写或置 0）。
4. `mid360.xacro`：`laser_max_range 200.0 → 40.0`（Mid-360 量程 40 m@10% 反射率 / 70 m@80%），
   `noise_stddev 0.002 → 0.02`（±2 cm 测距精度量级），并注明插件不读 `<noise>`。

### Behavior preserved

- topic 不变：`/livox/lidar`（CustomMsg）、`/livox/lidar/pointcloud`、`/livox/imu`。
- frame_id 不变：点云 `livox_frame`；IMU `imu_link`。
- LiDAR 出帧率 10 Hz、每帧 20000 点不变。
- `xyz`/`rpy` 雷达挂载 arg 默认值与 launch 组合不变。
- `base_link → livox_frame → imu_link` 的 TF 链仍完整、无环。

### Behavior intentionally adjusted

- IMU 发布频率 100 Hz → 200 Hz。
- IMU 输出叠加高斯噪声（原先无噪声）。
- LiDAR 最大量程 200 m → 40 m。
- IMU 空间位置随雷达参数移动，且与雷达同一刚体、相对位姿固定。

### Notes

默认雷达 arg `xyz="0 0 0.1" rpy="0 0 0"` 下，IMU 落在 `base_link` 的
`(0.011, 0.02329, 0.05588)` 处，是合理的"雷达壳内偏下"位置。
若以后把雷达挂载 rpy 改成 `3.14 0 0`（实物可能倒装），IMU 会自动跟随，
因为偏移量定义在雷达自身坐标系里。

### 回归修复（首次自检遗漏，用户实跑发现）

用户执行 `ros2 launch pb_rm_simulation rm_simulation.launch.py world:=RMUC2027` 报：

```text
[ERROR] [launch]: Caught exception in launch (see debug for traceback):
Unable to parse the value of parameter robot_description as yaml.
If the parameter is meant to be a string, try wrapping it in
launch_ros.parameter_descriptions.ParameterValue(value, value_type=str)
```

根因：`ros2_launch` 会把 `robot_description` 的展开字符串交给 `yaml.safe_load()`
（`launch_ros/utilities/evaluate_parameters.py:78`）。整段 XML 之所以以前能过，
是因为 PyYAML 把它当成一个跨行 plain scalar；plain scalar 内出现 **ASCII 冒号+空格**
（`": "`）会终止 scalar 并触发 `mapping values are not allowed here`。
本次新增的注释 `<!-- IMU joint: Mid-360 ... -->` 正好含 `": "`，于是 launch 直接崩。

修复：把该注释改成 `IMU joint 说明（...）`，并在注释里写明"不要出现英文冒号加空格"的坑。
修复后用 `xacro <install_share>/urdf/simulation_waking_robot.xacro` 生成的实际字符串
做 `yaml.safe_load()` 校验通过（返回 `str`），即与 launch 内部行为等价。

### Issues found

0. **`robot_description` YAML 解析崩溃（已修）**：新增注释里含 ASCII `": "`，导致 launch 报
   `Unable to parse the value of parameter robot_description as yaml`。已改写注释，
   并加入 `yaml.safe_load()` 静态校验环节。以后改 xacro 注释不要写英文冒号+空格。
1. 点云 `offset_time` 仍为插件构建耗时，而非 100 ms 扫描分布 —— 与 Gazebo 刚体快照自洽，
   保持现状；若将来要模拟真实运动畸变，需在插件里按帧周期分布 offset 并重新编译。
2. ray `<noise>` 插件不读，点云噪声仍为 0 —— 需改插件才能生效，本次未做。
3. IMU 无零偏（bias）模型，Gazebo 11 IMU 传感器与 `gazebo_ros_imu_sensor` 都不支持 SDF bias；
   影响有限（Super-LIO/ESKF 在线估计零偏）。
